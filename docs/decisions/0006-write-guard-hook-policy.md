# ADR-0006: 書き込み禁止フックの判定方針

- 日付: 2026-11-04
- 状態: 採用（開発者の指示による緩和）

## 背景

初版のフックは「コマンド文字列に `.dev.vars` / `demo/photos/` が含まれ、かつ書き込みらしい語があれば拒否」だった。
コードレビューと実運用で次の問題が確認された。

- 文書をヒアドキュメントで書くだけでも（本文に名前が出ると）拒否される
- `node -e` や `python -c` などインタプリタ経由の書き込みは検知できない
- `echo x >.dev.vars`（リダイレクト直後にスペースなし）が通る
- NotebookEdit が対象外

## 決定

`.claude/hooks/guard-writes.mjs` を次の方針に改める。

1. Write / Edit / MultiEdit / NotebookEdit は対象パスで判定する（`.dev.vars.example` だけ例外）
2. Bash はコマンドを `&&` `||` `;` `|` 改行で区間に分け、禁止パスを含む区間が「読むだけのコマンド」
   （cat, ls, head, tail, grep, wc, stat, diff, find など。区間にリダイレクトや tee があれば読むだけとみなさない）
   でなければ拒否する。許可リスト方式なので、インタプリタ経由の書き込みも拒否される
3. ヒアドキュメント本文は文章として判定から外す。ただし本文を sh / bash / node / python などに流すヒアドキュメントは本文も判定する（ヒアドキュメントごとに判定）

回帰テストは `scripts/check-hook.mjs`（`pnpm check:hook`。CI でも実行）。

## 影響

- `cat .dev.vars` のような読み取りは引き続き許可する。秘密の流出防止は本フックの目的外
- 引用符の中の `>` や区切り文字を厳密に扱わないため、まれに安全側（拒否）に倒れる。その場合は Write ツールで書く
