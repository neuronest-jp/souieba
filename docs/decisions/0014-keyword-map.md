# ADR-0014: ことばの地図（S6）は、Claude が言葉を選び、数と引用は Worker が本文から数える。中心は年

- 日付: 2026-11-07
- 状態: 採用
- 関連: requirements F10（末尾）、architecture 第13節（末尾）、wireframes 第10節（末尾）、ADR-0005（Structured Outputs）、ADR-0009（S5。シートと画面の行き来の作り）、ADR-0010（便箋と押し葉）、ADR-0011（動きと触覚の約束）

## 経緯

開発者の依頼: 「Claude が全投稿を分析して、テキストマイニングしキーワードマップを出せるようにしたい」。見本は、グループ（10 代・20 代・30 代）を中心に、それぞれの特徴的な言葉が周りに付き、グループどうしに共通の言葉が橋のように渡る図。
この作品では年齢を推しはからない（原則 1）ので、中心を「年」（起きた日の年）にする。期限は 11/8 の撮影と提出。並行して「これまでを年月で探す」（S2 の一覧の作り替え）が別の worktree で進んでいるので、S2 には入口しか足さない。

## 決めたこと

### 1. Claude は言葉と本文の形を選ぶだけ。数と引用は Worker が本文から数える

- `POST /api/keywords`（同期で Claude を 1 回）: その人の記憶を新しい順（一覧と同じ並び）に 200 件まで、本文と起きた日だけを渡す。本文の合計が 60,000 字を越える前で止める（1 件 2,000 字まであるので、待ち時間と量に上限を置く。依頼の「200 件まで」に足した上限）。
  Claude には「その人の暮らしを形づくっている言葉」を最大 40 個、`{ keywords: [{ label, kind: person|place|thing|event|feeling, surfaces: [本文に出てくる形のまま 1〜3 個] }] }`（`additionalProperties: false`）で選ばせる。
  プロンプト（`KEYWORDS_SYSTEM`）: 一般的すぎる語を除く、本文に無い言葉を作らない（まとめ言葉・言い換えにしない）、人物の年齢・感情・関係を推しはからない、気持ちは本文に言葉として書かれたものだけ。effort は low、待つのはこの呼び出しだけ 60 秒（`AiRequest.timeout_ms`。ほかは 20 秒のまま）。
- 検証（`verifyKeywords`）: surfaces は渡した本文のどれかに逐語で含まれる形だけ残す（エスケープを戻した形でも照合。1 字のかな・英数字は捨てる。漢字 1 字は残す）。残らなければ言葉ごと捨てる。label が本文に無いか、残った形のどれにも含まれなければ、残った最初の形に替える（本文に無い言葉を地図に出さない。本文の別の所にある語でも、数える形と結び付かないまとめ言葉を、ほかの形の回数と引用に付けて出さない。原則 1・3。プロンプトで頼むだけにせず、確かめる側で止める）。label の重複を除いて 40 個まで。
- 数え方（`worker/src/keywords/count.ts` の `buildKeywordMap`。Worker の決め打ち。Claude に数を言わせない）:
  - 記憶に「出てくる」= surfaces のどれかが本文の部分文字列（正規化しない。X-7）。1 つの記憶は何度出てきても 1 回
  - 年 = 起きた日の年。「いつだったか」の記憶は背骨に置けないので、数にも引用にも入れない（Claude には渡す）
  - 1 つの年だけに出る言葉は leaf（1 回でも出す。年ごとに回数の多い順に 4 つまで）、2 つ以上の年に出る言葉は bridge（8 つまで。つなぐのは回数の多い年 3 つまで、同じ回数なら新しい年。選ぶのは、まず合計の多い 2 つ、残りはつなぐ年の幅の大きい順、同じなら合計の多い順）。同じ数なら Claude が先に挙げた順。
    11/7 夜に実際の Claude と物語のデータで見ると、「合計 2 回未満は捨てる」「bridge は合計の多い順」では、短い日記では年の周りの言葉がほとんど残らず（2 つだけ）、「展望台」（2020 と 2023）が日々の言葉に押し出されたので、この形に改めた（幅の順だけにすると、隣り合う年に 17 回出る「そら」が落ちたので、合計の多い 2 つを先に入れる）
  - mentions: 新しい順に 10 件まで。各件は surface を含む本文の一文（。！？ と改行で区切る。括弧の中では区切らない）。原文のまま返し、画面が言葉の所に印を付ける
- 地図に出す言葉は、いまの本文に当たった形に含まれるものにする（label が消した記憶にしか無かったら、または当たった形と結び付かない語なら、いちばん多く出てくる形に替える）。

### 2. R2 には言葉の一覧だけを置き、見るたびに数え直す（D1 のマイグレーションは足さない）

- 置き場は写真と同じバケットの `maps/<user>/keywords.json`。中身は `{ version: 1, generated_at, memory_count, keywords: [{ label, kind, surfaces }] }` だけ（本文・引用・数は置かない）。`GET /api/photos/*` は `photos/<user>/` の下しか返さないので、画面から直接は読めない。
- `GET /api/keywords` は R2 の一覧を、いまの D1 の本文（起きた日の年が分かるもの、新しい順に 2,000 件まで）で毎回数え直す。だから消した記憶・直した本文の引用は出ず、2 回を割った言葉は地図から外れる（原則 5「削除は即時」と「記憶はその人のもの」）。自分の記憶だけを読む（X-11）。
- 記憶を消したら（`DELETE /api/memories/:id`）、その本文にだけ出てきた形を R2 の一覧からも外す（`forgetDeletedBody`）。画面は数え直しで消えるが、置き場に消した本文の断片（label・surfaces）を残さない（写真・候補・札・`ai_runs` と同じく、記憶と一緒に消える）。調べるのは消した本文に出てくる形だけで、残っている本文（「いつだったか」も含む）に 1 回の問い合わせで当てる。失敗しても記憶の削除は `204` のまま。
- `stale_count` は地図を作ったあとに書いた記憶の数（`created_at > generated_at`）。`generated_at` は Claude を呼ぶ前、記憶を読んだ時刻（待っている間に書いたひとことも「新しいひとこと」として数える）。
- 記憶が 8 件未満なら `POST` は 400（`few`）で、Claude を呼ばず、`ai_runs` も R2 も作らない。`GET` も `reason: "few"` を付ける。

### 3. Claude の失敗では地図を壊さない

- API の失敗・refusal・JSON の崩れ・タイムアウトは `ai_runs(kind='retrospect', status='failed')` に理由を残し、R2 には触らない。前の地図があれば `200` でそれを返し（`refreshed: false`）、無ければ `502`（`unavailable`）。再試行しない。
- 言葉が 1 つも残らなかったとき（`status='empty'`）、前の地図があれば上書きしない。無ければ空の地図を置き、画面は「もう少し書きためると、ことばの地図ができます。」と言う（「見つかりませんでした」とは言わない。原則 2）。
- `ai_runs` は CHECK 制約にある `retrospect`（F8 ふりかえりのための値）を使い、`memory_id` は NULL にする（`startAiRun` の `memoryId` を `string | null` にした）。記憶ごとの削除（`deleteMemory`）では消えない（どの記憶にも結び付かない呼び出しの記録で、本文を持たない）。
- 待っている間に画面を離れて接続が切れても、`waitUntil` に同じ処理を渡しているので、集めた地図は置かれる（次に開いたとき `GET` で出る）。

### 4. 画面（S6、wireframes 第10節）

- S2 の見出しの行の右に「ことばの地図 ›」の入口だけを足す（一覧には触らない）。`#words` は S3 と同じく push で入り、戻るは「‹ これまで」（左端からなぞっても戻る）。下部ナビの現在地は「これまで」。KeepAlive で残し（S3 から戻っても地図と位置はそのまま。待っている途中の集めも続く）、戻ったら「よみこみ中」を出さずに裏で取り直す。S6 から開いた S3 は `?from=words` で、戻るは「‹ ことばの地図」。
- 402pt の縦長で読めることを第一にする（見本の網の形をそのまま小さくすると読めない）。年を古い順に縦の背骨に並べ、leaf はその年の札の左右に（回数の多い順に 右・左・右・左）、bridge は年と年のあいだの行の左右に置き、言葉の内側の縁から、つなぐ年の札それぞれへ、細い朱の実線の糸を 1 本ずつ渡す（なめらかな 3 次ベジェ曲線。両端は横向きに出入りする）。
  糸は 1px、不透明度 50%（`stroke-opacity`）で控えめにし、年の札の縁（2px 外）に半径 2px の朱の小さな結び目（`fill-opacity` 60%。年と側ごとに 1 つ）を置く。ふくらみ（制御点の x）は年の札の縁から 6〜21px で、側ごとに、つなぐ年の端から端までが長い糸ほど背骨の近くを通す（あいだの年の言葉から離す）。言葉の縁には 14px より近づけない。どの糸も背骨と言葉のあいだだけを通るので、言葉の文字には重ならない（細い糸どうしは交わることがある）。
  糸は破線にせず、細い実線にする。糸が表すのは Worker が本文から数えた「どの年に何回出るか」という事実で（1 節）、言葉を選ぶのが Claude でも、どの年に結ぶかは推測ではない。だから S5 の「確かめる前」のしつけ糸（破線。確定の見た目にしない。原則 1）とは分ける。
  字は回数で 13〜17px、収まらなければ小さく、それでも収まらなければ 2 行。並べ方は `web/src/words/layout.ts`（純粋関数。測らずに位置を決める）。
- 糸の描き方の経緯: 最初は曲線で引いたが、402pt で 8 本の糸が背骨の脇で絡んで読めなかったので、11/7 に、背骨の脇の自分の通り道（言葉ごとに 6px ずつ外へ）を縦に通る朱の破線（地下鉄の路線図のような角を丸めた折れ線）にした。
  11/7 夜に開発者が実機で見て「赤い線の繋げ方が少しダサい」と言ったので、3 案を描き分けた（糸: 上の形 / 弧: いちばん古い年と新しい年を背骨の片側の弧で結び、言葉を弧の頂点から短い糸で吊るす / 控えめ: 墨の薄い点線と、言葉の側の朱の小さな印）。開発の間だけ URL の `?lines=` で切り替えて見比べ、開発者が糸を選んだ（切り替えと、弧・控えめ・通り道の形は外した）。
  最初の曲線が絡んだ心配には、細さ（1px）・不透明度（50%）・言葉の縁から 14px 離す決まり・長い糸ほど背骨の近くを通す決まりで応えた（`web/test/wordsLayout.test.ts` で、402pt と 375pt の幅で線が言葉の箱に入らないことと、ふくらみの決まりを確かめる）。
- 言葉を押すと下からのシート（`useSheetDrag`。DateSheet・PairSheet と同じ手ざわり）で、その言葉が出てくるひとことを新しい順に日付と一文で並べ、言葉の所に蛍光ペンの印（読み上げは「」）。押すと S3。シートを開いたまま画面を離れたら閉じる。
- 状態: 地図が無い →「ことばを集める」/ 待つ間 →「ことばを集めています」（`role="status"` を初めから置いて文字だけ入れ替える。しつけ糸の目が縫われる小さな動き。地図があれば地図を少し薄くしてそのまま見せる）/ 8 件未満・言葉が残らなかった →「もう少し書きためると、ことばの地図ができます。」/ 集められなかった →「いまは、うまく集められませんでした。少し時間をおいて、もう一度どうぞ。」と「もう一度」/ 新しいひとことがある →「新しいひとことが N こあります。集めなおす」/ 集めなおせなかった →「いまは集めなおせませんでした。もう一度」（地図は前のまま）。
- 動き（ADR-0011 の 6 節の約束。`styles/words.css`）: 地図が現れるとき（集めたときと最初に開いたとき）だけ、背骨が上から伸び（460ms）、年の札が 120ms から 60ms ずつ、言葉が 260ms から 35ms ずつ（30 こまで）6px 下から浮かび、線と糸（結び目も）はつながる言葉と同じ順に 220ms から 35ms ずつ薄く現れる。transform と opacity だけで、動きを減らす設定では付けない。
- 触覚（ADR-0011 の 3 節の表に足す）: 集め終えたら `saved`、集められなかったら `failed`（どちらも利用者が押したことの結果。待つ間は鳴らさない）。言葉を押してシートを開くときは鳴らさない（S5 の組と同じ）。

## 時間が無いときに削る順

1. 地図が現れる動き（`is-weaving` を付けない）
2. 左端からなぞって戻る（戻るボタンは残る）
3. S2 の入口（`#words` を直接開けば使える）

## まだのこと

- 実際の Claude（Opus 5.5、effort low）で、物語のデータ（77 件）が 60 秒に収まるか、どんな言葉が選ばれるかを見ていない。iPhone の WebView の通信が 60 秒を越えたときの振る舞い（URLSession の既定の 60 秒に近い）も見ていない
- 同時に 2 回集めたら、あとから終わった方が残る（画面はボタンを隠すので、ふつうは起きない）
- 集めている間（Claude を待つ数十秒）に記憶を消すと、Claude に渡した本文から選んだ形が、消したあとで置き場に書かれることがある。見るたびに数え直すので画面には出ず、次に集めなおせば外れる。Claude の答えのあとで記憶がまだあるかを確かめ直すことはしていない
- 部分文字列で数えるので、「泣き」が「夜泣き」に、「海」が「海老」に当たる。形を選ぶのは Claude なので、プロンプトで「本文に出てくる形のまま」と頼むだけにした
- bridge は 8 つまでなので、離れた年をつなぐ言葉が 8 つより多いときは、幅の小さいものが落ちる（11/7 夜に、回数の順から幅の順に改めた）
- 地図の中で言葉どうしが重ならないことはテストで確かめたが、実機の文字の幅（見積もりより広い字体）では確かめていない
