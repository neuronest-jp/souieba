- 根拠: docs/spec.md v0.3 第6節（画面一覧）、第3.1節（主要な流れ）、第5節（非機能）、第10節（認証）。受け入れ条件は docs/requirements.md の ID で参照する。配布は Capacitor（iOS / Android）、ログインは招待コード + メールアドレス（ADR-0007）
- 実行環境: Capacitor の WebView（セーフエリアは `env(safe-area-inset-*)` で確保。ステータスバーとスプラッシュは地の色 `#FAF5EC`）。ブラウザ（`pnpm dev` / `pnpm preview`）は開発プレビューで、同じ画面が出る
- デザイン: ADR-0004（カラー・フォント・動き）。トークン名は `web/src/style.css` の `@theme` と同じ（本文フォントは `font-body`）
- API の形: docs/architecture.md 第5節を正とする（`{pending, items}`、`PATCH /api/facts/:id` は `{status: "confirmed" | "rejected"}`（tasks J-7）、`GET /api/memories/:id` に `recalled_by`）。requirements.md の `{status: "pending"|"done"}` / `{status: "confirmed"}` は tasks J-7 のとおり読み替える（第8節 #12）
- 画面遷移: docs/architecture.md 第7節（ハッシュ `#today` / `#past` / `#memory/<id>`、vue-router なし）
- 想定幅: スマホ縦 375px。図の枠は内側 40 セル（全角 1 文字 = 2 セル）。PC では中央 560px に収めて同じ構成
- 図中の `[ ]` はボタン、`( )` は入力欄、`▭` は写真、`‹` は戻る、`▒` は本文中の引用の強調

## 1. S0 ようこそ（ログイン）

#### いつ？のシート（起きた日と精度）

F2「起きた日（既定: 今日。精度: 日/月/年/不明）」は過去の日付を入れることが前提なので、精度だけでなく日付そのものを変えられるようにする。依存は足さず、ブラウザ標準の入力を使う。

```
├────────────────────────────────────────┤
│ いつのこと                             │
│                                        │
│  [ 日 ]  [ 月 ]  [ 年 ]  [ いつだったか ] │
│                                        │
│  ( 2025年6月15日            )          │
│                                        │
│               とじる                   │
└────────────────────────────────────────┘
```

| 要素 | 文言 | トークン・余白 |
|---|---|---|
| 精度 | 日 / 月 / 年 / いつだったか | 小さな選択（そう / ちがう と同じ形）。選択中は `bg-ember-soft` + `border-ember`。既定は「日」（`happened_on_precision = 'day'`） |
| 日付 | （精度に応じて 1 つだけ出す） | 日: `<input type="date">`、月: `<input type="month">`、年: `<select>` に今年から 100 年前までを降順で。いつだったか: 入力欄を出さない。どれも `bg-card` + `border-line`、高さ 44px、17px。既定値は 2.1 と同じ `Asia/Tokyo` の今日（年の選択肢の「今年」も同じ基準）。月や年だけ変えたときは、日をその月の末日に丸める（10/31 のまま 11 月にすると 11/30。存在しない日付のまま「日」に戻して保存できなくならないように） |

## 6. アクセシビリティ

| 項目 | 指針 | 根拠 |
|---|---|---|
| タップ領域 | すべて 44×44px 以上。「そう」「ちがう」「いつ？」「はずす」「消す」「やめる」のような小さな文字のボタンは `padding` ではなく `min-height: 44px` + 透明な余白で確保 | 本書 0 節 |
| 文字サイズ | 本文 17px を下回らない。14px は補足（日付、種別、添え書き、「ひらく ›」のような札全体がタップ領域のラベル）だけで、それ単独で意味が完結する文には使わない。ユーザーのフォント設定（`rem`）に追従する | 第5節 |
| コントラスト（地 paper / card に対して） | `ink` 約 11.5:1、`ink-soft` 約 5.2:1 は本文・補足に使える。`ink-faint` は約 2.5:1 で AA を満たさないため、プレースホルダ、押せないボタンの文字（WCAG の対象外）、装飾にだけ使い、日付・候補の種別・「よみこみ中」・「写真を読めませんでした」のような意味を持つ文字には使わない（`ink-soft` にする）。`ember` 約 3.7:1、`moss` 約 3.2:1 は文字色としては 22px 以上の太字（大きな文字 3:1）に限り、それ以外は線、地（`-soft`）、縁、`bg-ember` のボタンに使う。本書で `text-ember` を使うのは札と履歴の「そういえば。」（22px / 700）だけ | ADR-0004 の値から算出 |
| 色だけに頼らない | 確定は色に加えて「✓」、却下は薄さに加えて「そう」「ちがう」が消えること、反応は選択状態に加えて `aria-pressed`、下部ナビの選択中は色でなく、絵の後ろの地とその `ember` の縁（paper / card に対して約 3.7:1）、太字、`aria-current="page"` | |
| 動き | 札のフェード（`.appear`）は `prefers-reduced-motion: reduce` で無効。自動で動くものは他に無い | architecture 8.1、style.css |
| 構造 | 画面ごとに `h1` は 1 つ（S1 は起きた日、保存後は「残しました」/ これまで / 起きた日 / ふりかえり）。札は `article`、候補の行は `li`、「そう」「ちがう」は `button`。本文中の強調は `mark`（`bg-ember-soft` を当てる）。画像には本文 1 行目を `alt` に入れる | |
| フォーカス | キーボード操作時は `outline` を `ember` 2px で出す（style.css の `:focus-visible`）。PC で崩れない（第5節）。「そう」「ちがう」をキーボードや読み上げソフトで押したときは、押したボタンが消えるので、フォーカスをその行（S3 の却下で行が消えたときは同じ位置の行、無ければひとつ前の行、それも無ければ見出し）へ移す。指やマウスで押したときは動かさない（S1 では記憶カードの `:focus-within` の縁が光ったまま残るため）。選んだ結果は、候補の一覧に置いた見えない `role="status"` で「（値）、そう」「（値）、ちがう」と読み上げる。画面を切り替えたとき（ハッシュが変わったとき）は、押したリンクごと前の画面が消えてフォーカスが body に落ち、読み上げで新しい画面が伝わらないので、新しい画面の `h1` へフォーカスを移す（下部ナビから移ったときも同じ。位置は動かさない）。S3 は読み込みが終わってから `h1` に置く。S1 で保存したら「残しました」、「もうひとつ書く」で戻ったら起きた日の `h1` へ（入力欄に置くとスマホでキーボードが勝手に開くので置かない）。ログインした直後も S1 の `h1` へ。`h1` の `tabindex="-1"` は置くあいだだけ付け（指で見出しに触れてもフォーカスが移らないように）、`h1` には枠を出さない。読み込みを待つ間に利用者がほかへ動かしたフォーカスは奪わない | |
| 入力 | 入力欄は `textarea`、`enterkeyhint="done"`。Enter は改行で、保存はボタンだけ。日付は `<input type="date">` / `<input type="month">` / `<select>`（2.1） | |
