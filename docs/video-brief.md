# デモ動画のための整理（11/7 夜）

別のセッションで動画の構成を固めるための下敷き。どんなアプリで、何を見せられて、撮るときに何に気をつけるかを 1 か所にまとめた。
細かい台本の案は `docs/demo-video.md`、撮影のデータと実測は `demo/fixtures/README.md` の「物語のデータ」、コンセプトの原文は `README.md`。

## 1. 提出と動画の決まり

- 提出締切: **2026-11-08（日）20:00 JST**。提出物は、プロジェクト名・テーマ・説明（500 字以内）・**デモ動画（3 分以内）**・公開 GitHub リポジトリ・Claude Code での開発の感想
- 動画: **3 分を超えると減点、3 分より後は見ない**（書き出しは 2:50 以内が目安）。YouTube・Loom など（限定公開で、ログインしなくても見られること）。**期間中（11/3〜）に作った機能・コードだけ**を映す
- 第 1 ラウンド（11/9）で全作品から上位 6 チーム。第 2 ラウンド（11/10 13:00〜）は**事前収録の 3 分デモを再生**し、審査員が話し合う
- 審査の観点:
  - インパクト 30%: 課題が具体的な暮らし・現場から出発しているか。誰が、どんな場面で、どれくらい困っているか。ハッカソン後も使い続けるか（テーマ 2 は、これまで届いていなかった具体的な人と、その壁を取り除くこと）
  - デモ 25%: **冒頭で誰の・どんな課題を・どう解決するか**が明確か。前提知識が無くても操作の流れで価値が分かるか。最後まで見たくなるか
  - Claude の活用 25%: 基本を超えた使い方。Claude Code を開発の中心にして何ができたか。Skills・サブエージェント・MCP・フックの使い分け
  - 深さと実行力 20%: 試行錯誤して磨いた跡。設計と実装の作り込み。困っている人が安心してそのまま使える仕上がり

## 2. どんなアプリか（ひとこと）

**「そういえば。」**: ひとことと写真 1 枚を残しておくと、あとで新しいひとことを書いたとき、関係のある昔の記憶が、そのときの言葉のまま「そういえば。」と浮かんでくる iPhone アプリ。

## 3. コンセプト（README の「どんな困りごとから」、開発者が目を通した文）

- 秋田で暮らしていて気づいたこと: 誰から何をもらったか、あの人は何が好きで何が苦手か、何をしてみたいと言っていたか。そういう小さな記憶が、次の気遣いや人とのつながりを支えている
- 一方で、Claude のような AI と話すなかで「以前話したことを踏まえてくれる」便利さに助けられている。覚えていてくれる相手がいると、暮らしは少し楽になる
- でもその便利さは、まだ AI と話す人のもの。スマートフォンは使うが、AI に日常を話す習慣はない人に届けたい（**テーマ 2**。届く相手は仮説として書く）
- 入口は毎日のひとこと。きちんとした相談を考えなくていい。「スーパーで青梅を見かけた」と書くだけで、昔の梅干しの記憶がそのときの言葉のまま浮かぶ
- 結び: 「日々の小さな記憶が、あとの暮らしにもう一度つながる。そのとき自然に口から出る『そういえば』を、大切にしたくて作りました。」
- 方針: 開発者の実体験としては書かない。「田舎」「村」は使わない。通知・共有・検索を匂わせない

## 4. 画面と機能

下部ナビは **きょう / これまで / つながり** の 3 つ。画面に「AI」という言葉は出さない。

| 画面 | 見せられること |
|---|---|
| ログイン（S0） | 招待コードとメール。パスワードは無い（動画では映さなくてよい） |
| **きょう（S1）** | 便箋に書く。日付で替わるあいさつと問いかけ。「いつ？」で日付（日・月・年のどれかでざっくり）。写真 1 枚。**このごろ**（7 日分の押し葉。続けた日数は数えない）。**あの日のひとこと**（去年以前のいまごろの記憶。「1年まえの、きょうのころ」）。保存すると手書きの ✓ と「N こめのひとこと」と触覚 |
| きょう → **札** | 保存して 2〜7 秒で、関係のある昔の記憶が一筆箋（封蝋つき）で浮かぶ（最大 3 枚）。**当時の原文の引用**と、なぜ思い出したかのやわらかい一文。待つ間は糸がゆれて「思い出しています」。関係が無ければ何も出ない。最初の札は見える所まで送られる |
| きょう → **控え** | 「ひとことに出てきたもの」: 人・場所・もの・日付の候補。**「そう」「ちがう」**で決める（「そう」で判が押される）。写真を添えると**「写真から」「〜でしょうか」**の候補も並ぶ。決めるまで事実にしない |
| 詳しい（S3） | 札を押すと昔の記憶へ。本文の引用の所に印。札に「そうだった」「関係ないかも」と返す（そうだったは本縫いになる）。左端からなぞって戻る。消すときは確かめてから |
| これまで（S2） | 時系列の静かな一覧 |
| **つながり（S5）** | 上に糸の帯（年の上に記憶の粒、結ばれた組を弧で）。下にふたつの日の組（今日のひとこと ↔ 思い出された日、「2年5か月まえの、あのとき」）。組を押すとシート |
| 手ざわり | 画面の移り変わり、なぞって戻る・シートをなぞって閉じる、押した直後だけの触覚、鍵盤の上に残る「保存する」、季節で替わる押し葉と封蝋の模様、夕方（17 時〜）と夜（21 時〜）は地の紙が灯りの色に寄る。「動きを減らす」設定では動きを止める |

**11/7 夜に足した 2 つ**（取り込み済み。Simulator で確かめた。実機には 11/7 夜に入れた）:
- **ことばの地図**（これまでの見出しの右「ことばの地図 ›」から入る）: 年を縦の背骨に、その年に出てくる言葉が周りに、年をまたぐ言葉から朱の細い糸が年へ渡る。
  言葉は Claude が選び、数と引用は Worker が本文から数える。物語のデータでは 7 秒ほどで集まり、「山の上の展望台」が 2020 と 2023 をつなぐ。
  言葉を押すと「2020年・2023年に、あわせて 2 こ」と、その一文が原文のまま印つきで並ぶ。初めては「ことばを集める」を押す（実機の DB では一度押しておく）。
  2020 年の周りに「離婚届」、2024 年に「役所」「婚姻届」が出ることがある
- **年月でたどる**（これまで）: 一覧が年月ごとに区切られ、左上に「2026年 11月 ⌄」の札が浮かぶ。押すとシート「年月でたどる」で、年ごとの 12 か月のマス（件数つき、無い月は薄く）から選んでその月へ。上に「↑ いちばん新しいひとことへ」
- README の写し: docs/images/（書く・札・つながり・年月でたどる・ことばの地図・言葉のシート）

## 5. 変えない原則（動画で見せられる所）

| 原則 | 見せ方 |
|---|---|
| 推測を事実として確定しない | 控えの候補は「そう」で決まる。写真の候補は「〜でしょうか」 |
| 関係なければ何も言わない | 関係の無いひとこと（例「シャンプーの詰め替えを買った」）では札が出ない |
| 必ず原文を添える | 札の引用は当時の本文そのまま。S3 で本文のその所に印 |
| 記憶はその人のもの | 消すと写真も札も記録も一緒に消える |

## 6. Claude の使い方（事実だけ）

**作品の中**
- 思い出す・候補を出す・写真から候補を出すのは Claude（既定 `claude-opus-5-5`）。Worker から呼ぶ
- 答えの形は Structured Outputs（JSON Schema）で固定。**Worker が引用を一字ずつ原文と照らし**、本文に無い引用・ほかの人の記憶・4 件目以降を捨てる。関係が無ければ 0 件を正しい答えとして何も出さない
- 用途ごとに effort を分け（候補 low・想起 medium）、決まった指示はプロンプトキャッシュに乗せる

**開発の中（Claude Code を真ん中に）**
- 仕様書の組み直しから、判断の記録（**ADR 13 本**。試して戻した判断も残す）、実装、テスト（**523 件**、CI 5 段）、iPhone 実機への入れ込みまで
- **ワークフロー（複数のサブエージェント）**: 見た目とつながり画面の案を 3 体ずつ並行で作って選んだ。見直しは「見つける役」と「反証する役」を分け、反証に耐えた指摘だけ直した（4 回。見つける役 26 体 → 反証 148 体）。11/7 夜の提出前の点検は 6 観点・100 体
- **MCP**: iOS Simulator（ビルド・起動・写し・タップ・鍵盤の高さを測る）、組み込みブラウザ
- **フック**: `.dev.vars`・デモの写真・署名ファイルへの書き込みを拒む（回帰テスト 39 件）。画面の禁止語（AI・生成・送信）と色の直書きは CI で止める
- **Skills**: くり返す手順（実機への入れ込み・デモの DB の戻し・提出用の履歴づくり）をプロジェクトの Skill に
- 画面素材の候補: ワークフローの進み、ADR の一覧、`pnpm check:hook` の `ALL OK (39)`、Simulator の写し。フックが拒む場面は記録に無いので、映すならその場で再現する

## 8. 書く一文と、実際に浮かんだ札（11/7 夜、実際の Claude）

札の数・言い回しは撮るたびに少し変わる。

| 書く一文 | 浮かんだ札 | 秒 |

| そろそろクリスマスのプレゼントを考えたい。みさきは何がうれしいかな。 | 雑貨屋の「このガラスのコップ、いいな」/ 去年のマフラー / おととしの手袋と「来年は三人だね」の 3 枚 | 6 |

## 10. 撮影の段取りと気をつけること

- 端末: iPhone 16 Pro。いまは**開発者の Mac の LAN の Worker**（`pnpm dev:worker:lan`）につないでいて、DB には物語のデータ（コンセプトに合わせた版）が入っている。撮り直すたびに `pnpm db:seed:story:local`（`.claude/skills/demo-reset`。実機で書いたものは消える）
- 本番の Worker はまだ無い（deploy は開発者。手順は `docs/submission.md`）。LAN で撮るなら要らない
- **時間帯で地の紙の色が変わる**（17 時から夕方、21 時から夜）。場面ごとに色が変わらないよう、全部を同じ時間帯（昼）に撮る
- 展望台の写真は開発者が撮ったものを iPhone の写真ライブラリに入れておく（データの 2020 年 7 月の記憶には写真が無い）
- 札が出るまで 2〜7 秒。編集で詰めるときは「待ち時間を短縮」と小さく出す
- 撮るたびに `ai_runs` の status を見て、failed があれば DB を戻して撮り直す
- 集中モードで通知を止める。画面収録はコントロールセンターから。日本語の入力に時間がかかるところは編集で詰める
- 実機で確かめ済み: ダブルタップで拡大しない、写真を選べる。触覚は分かりにくい（設定の「システムの触覚」が要る。「保存する」の直後がいちばん分かる）
- 映さないもの: 期間前のコード、旧作品、他人の写真や権利の無い素材、`.dev.vars` や招待コード
