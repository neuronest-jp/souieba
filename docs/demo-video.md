# デモ動画の構成（3 分以内・提出用）

審査の「デモ（25%）」は、冒頭で誰の・どんな課題を・どう解決するかが分かること、前提知識が無くても操作の流れで価値が伝わること、最後まで見たくなることを見る。
3 分を超えると減点され、3 分より後は見てもらえない。**書き出しは 2:50 以内**を目安にする。期間中（11/3〜）に作った機能だけを映す。

`【要記入】` は開発者にしか書けないところ（自分の体験、テーマ、ハッカソン後に誰が使うか）。作り話で埋めない。

## 場面ごとの台本

ナレーションは 1 分に 300 字前後の早さで読む。画面の文字を読み上げない（同じことを二度言わない）。

### 0:00–0:07 つかみ

- 画面: iPhone の S1。便箋に「スーパーで青梅を見かけた」と書いて「保存する」。糸がゆれて、一筆箋の「そういえば。」が浮かび、
  引用「おばあちゃんは毎年6月になると、縁側で梅干しを漬けていた。」が出る（待ち時間は編集で詰める）
- ナレーション: なし。触覚の音と画面だけ。最後に題字「そういえば。」

### 0:07–0:25 誰の・どんな課題を・どう解決するか

- ナレーション（案）:
  「【要記入: 開発者自身の体験をひとこと。例の形: ○○との思い出を書き残してきたけれど、読み返すことはほとんど無かった】
  大切な人との記憶は、書き残しても、読み返さなければ眠ったままです。
  『そういえば。』は、ひとことと写真 1 枚を残しておくと、あとで新しいひとことを書いたとき、関係のある昔の記憶を、そのときの言葉のまま返してくれます。」
- テーマ 1 で出すなら「その世界に身を置いてきた人だから見えた足りないもの」を、テーマ 2 なら「これまで届いていなかった具体的な人と、その人を阻んでいた壁」を、この 18 秒に入れる【要記入: テーマ】

### 0:25–1:05 D1 祖母の梅干し

1. S1 を開く。時間帯で替わるあいさつと問いかけ、このごろの押し葉（7 日分）、あの日のひとこと（2 秒で十分）
2. 書く →「保存する」→ ✓ と「N こめのひとこと」、触覚
3. 糸がゆれて「思い出しています」→ 札。理由と、2024 年に書いた原文の引用
4. 札を押す → 2024 年の記憶（S3）を開く → 左端からなぞって戻る
5. 候補（青梅・スーパーなど）を「そうだった」→ 判が押される

- ナレーション（案）:
  「関係があると判断した昔の記憶だけを、理由と、その日に書いた言葉の引用を添えて出します。引用は、本当に昔の本文の中にあるかを確かめてから出しています。」
  「人やもの、場所は候補として出るだけです。『そうだった』と押すまで、記憶には入りません。」

### 1:05–1:20 D2 電気代

- 画面: 「電気代を払った。先月より少し安かった」→ 保存 → 何も浮かばない（✓ だけ）
- ナレーション（案）: 「関係が無ければ、何も言いません。無理につなげないことも、このアプリの大事な答えです。」

### 1:20–1:45 D3 公園の花（写真があるとき）

- 画面: 開発者が撮った公園の花の写真を添えて「公園で花が咲いていた」→ 候補「桜でしょうか」→「ちがう」→ 記憶にも検索にも入らない
- ナレーション（案）: 「写真から見えたものも『〜でしょうか』と尋ねるだけ。違えば、それは残りません。推測を事実にしないためです。」

### 1:45–2:05 D4 はるとの自転車とつながり

- 画面: 「はると、今日補助輪なしで乗れた」→ 札「はるとが三輪車で転んで泣いた。…」→ 下部ナビの「つながり」→ 前に見たときより後に結ばれた組に糸が渡される → 組を押してシートを開く
- ナレーション（案）: 「書きためるほど、昔の記憶と今日のひとことが、つながっていきます。」

### 2:05–2:35 Claude の使い方

数字は `docs/submission.md` の棚卸し（事実だけ）から入れる。画面は短いカットをつなぐ（ターミナルのワークフローの進み、ADR の一覧、フックが署名ファイルへの書き込みを拒む場面、Simulator の写し）。

- 作品の中（案）: 「思い出すのと候補を出すのは Claude です。答えの形を JSON Schema で固定し、Worker が引用を原文と照らしてから画面に出します。関係が無ければ 0 件を返します。」
- 開発の中（案）: 「7 日間、Claude Code を開発の真ん中に置きました。仕様から判断の記録（ADR）まで、秘密と署名ファイルを守るフック、画面に技術の言葉を出さない検査、
  複数のエージェントでデザイン案を比べ、見直しの指摘は別のエージェントが反証してから直す。iPhone のビルドと画面の確認も Claude Code から。」【数字を入れる: ADR の本数、ワークフローとエージェントの数、見直しの回数、テストの数】

### 2:35–2:45 締め

- ナレーション（案）: 「【要記入: ハッカソンのあと、誰がどんな場面で使い続けるか。例の形: 私は毎晩、子どもの寝顔を見たあとにひとこと書いています】
  書いたひとことが、いつか『そういえば。』と話しかけてくれます。」
- 画面: 題字「そういえば。」とアイコン（封蝋）

## 録る前の確かめごと

- **つなぐ先の DB**: iPhone がつなぐ Worker の DB に、デモの過去の記憶（`demo@example.com` の 16 件、D1 の梅干し `mem_d1_01`、D4 の三輪車 `mem_d4_01`）が入っていること。
  録り直すたびに `pnpm db:seed:local` で戻す（D1 の行は消えて入れ直される。R2 の写真は残る）
- **本番で録るなら**: 本番の Worker の deploy（`GET /api/today` を含む）、本番の D1 にデモの記憶、画面を本番の `VITE_API_BASE` でビルドしてから入れ直す。手順は `docs/setup-cloudflare.md`
- **時間帯の紙**: 17 時から地の紙が夕方の灯りの色に寄り、21 時からは夜の色になる。場面ごとに色が変わらないよう、全部を同じ時間帯（昼）に録る
- **写真**: D3 は開発者が権利を持つ公園の花の写真を、iPhone の写真ライブラリに入れておく（`demo/photos/` は開発者が置く）
- **待ち時間**: 札が出るまで数秒かかる。編集で詰めるときは、画面の隅に「待ち時間を短縮」と小さく出す（見る人を誤解させない）
- **端末**: 集中モードで通知を止める。画面収録はコントロールセンターから（音を入れるならマイクを入れる）。文字の入力に時間がかかるところは編集で詰める
- **長さ**: 書き出したら長さを確かめる（2:50 以内）。YouTube は限定公開で、ログインしなくても見られるか別の端末で確かめる
- **映さないもの**: 期間前のコード、旧 Yui（雪かき）の画面や履歴、他人の写真や権利の無い素材、`.dev.vars` や招待コードの画面

## 決めてもらうこと

2. 締めの「ハッカソンのあと、誰がどんな場面で使い続けるか」
3. D3 を入れるか（公園の花の写真を用意できるか）
4. 録る先: LAN の Worker（いまの iPhone の設定のまま）か、本番か
