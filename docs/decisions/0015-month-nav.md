# ADR-0015: 「これまで」（S2）を年月で探す。区切りは起きた日、札は sticky、探すのは月から読み直す形

- 日付: 2026-11-07
- 状態: 採用
- 関連: requirements F3（末尾の「F3 追記: これまでを年月で探す」）、wireframes 末尾の「S2 を年月で探す」、architecture 末尾の「年月で探す」、ADR-0010（便箋と押し葉）、ADR-0011（触覚・動き・シート）

## 経緯

開発者の依頼: 「これまでのページを年月で探せるようにしたい。こんな感じで左側に日付を出していけるように」。
見本は iPhone の写真アプリのライブラリで、スクロールすると左上に「2025年」「2026年」の札が浮かび、区切りごとに替わる。

S2 は起きた日の降順の静かなリスト（F3-1）で、20 件ずつ「もっと前を見る」で足す（F3-3）。記憶が増えると、数年前の月まで指でたどるしかなかった。
デモの物語のデータ（demo/fixtures/story.sql）は 2020-04 から 2026-11 まで 77 件で、ほとんどの月が 1〜3 件になる。

## 決めたこと

### 1. 区切りは起きた日（書いた日ではない）

- 一覧の並びが起きた日の降順なので、区切りも同じ物差しにする。書いた日（created_at）で区切ると、並びと区切りがずれて同じ月が何度も割れる
- 精度ごと: day と month はその年月（「2025年 11月」）、year は年だけ（「2025年」）、日付の無い記憶（unknown）は最後に「日付なし」
- 年だけの記憶は API の丸め（validate.ts）で `YYYY-01-01` に並び、同じ日の 1 月の記憶（1 月 1 日の day、1 月の month）と作成の順で混ざる。
  並び（LIST_ORDER）は変えず、画面（`web/src/past/sections.ts`）で**起きた日が同じ行の中だけ**年だけの記憶を後ろへ回す。
  これで「2025年 1月」の区切りが割れず、その後ろ（古い側）に「2025年」（その年のいつか）が来る。続きを足しても同じ起きた日の行は続いて届くので、区切りの順は崩れない
- 年だけの記憶を月に割り振らない（推測を事実として確定しない）。日付なしも同じ
- 札は今年でも年を付ける（「2026年 11月」）。写真アプリと同じく、年をまたいでスクロールしても迷わない

### 2. 札は position: sticky（スクロールを測らない）

- 区切りごとに `<section>` を作り、その頭の `<h2>` を `position: sticky`（上は `env(safe-area-inset-top) + 8px`。ステータスバーの地の下）にする。
  区切りの箱の終わりで札は止まり、次の区切りの札がちょうど前の札を押し出して替わる。JS でスクロールを測らないので、iPhone でも重くならず、動きを減らす設定でも何も変えなくてよい（動きではなく位置）
- `<section>` は `display: flow-root` にする（11/7 の見直し）。普通のブロックだと、区切りの箱を罫の 9px 上で終わらせるための ul の `margin-bottom: -9px` が
  section の外へ相殺され（CSS2.1 8.3.1）、箱が罫まで伸びて、受け渡しのたびに前の札と次の札が 9px 重なっていた。flow-root で箱の中に留めると、
  行の位置は変わらず重なりが 0 になる（headless Chrome の 402×874 で測った）
- 札（高さ 24px の小さな紙の札。`bg-card`、`border-line`、`rounded-pill`、`shadow-card`、14px、下向きの小さな山形）は、前の区切りの最後の行の罫にまたがって置く（罫の 9px 上から 15px 下まで）。
  区切りの最初の行は上に 12px 足し、行の文字（写真の行は焼き付け）が札の 9px 下から始まるようにする。止まっている間は文字を隠さない。上に貼り付いた札がスクロールする行の上に重なるのは写真アプリと同じ
- 札の行（h2）は横いっぱいの帯なので `pointer-events: none` にして、札だけを押せるようにする。押せる所は `::after` で上下に 44px まで広げる
- 見出しの行（「これまで」と押し葉）は sticky にしない・触らない（右にもう 1 つの機能の入口「ことばの地図 ›」が入る）

### 3. 探すのは「月から読み直す」形

- 一覧はキーセットのカーソルで 20 件ずつ読む（F3-3）。全件を持っていないので、古い月へ飛ぶには、その月から読み直す。
  `GET /api/memories?month=YYYY-MM` は `COALESCE(happened_on,'')` が翌月の 1 日より小さい行から、今の並び（LIST_ORDER）のまま返し、続きは今までどおり `next_cursor`
- **仕様からの追加**: シートから年だけ・日付なしも選べるよう、`year=YYYY`（年だけの区切りから。上限は 1 月 2 日）と `undated=1`（日付なしから。上限は `"0"`）を足した。
  どれも「`COALESCE(happened_on,'')` の上限」1 つで表せるので、SQL は 1 つの形（`buildListSql(cursor, before)`）で済む。cursor と始まりが両方あれば cursor を優先し、形の誤り・2 つ以上は 400
- `year=` は同じ 1 月 1 日の 1 月の記憶も前に入る（並びの上で年だけの記憶と分けられない）。画面は、行き先の区切りが先頭でなければ、その区切りの頭へ送る
- 件数（`GET /api/memories/months`）は札を押したときだけ読む（一覧の読み込みを増やさない）。2 回目からは前の結果をすぐ出し、裏で取り直す
- 読み直したら、新しい一覧の最初の表示として `.rise-in` で現れる。位置は待たずに先頭へ（`smooth` にしない。何年分もの距離を滑らせない）。
  読み直している間は前の一覧を出したまま（`aria-busy`）。失敗したら一覧の所に「読み込めませんでした」「もう一度」（同じ始まりで読み直す）と「いちばん新しいひとことへ」
- 戻るのは一覧の先頭の「いちばん新しいひとことへ」。行き先の月から**上へも**読み足す形（両方向の続き）は、位置の保ち方と KeepAlive の取り直しが込み入り、期間内に確かめきれないので入れない
- 読み直したあとも、S3 から戻ったときの取り直し（見えている件数ぶん）と「もっと前を見る」は同じ始まりのまま（`start`）。KeepAlive の位置もそのまま

### 4. 写真アプリのような指で掴むつまみは付けない

写真アプリには、右端を掴んで上下に滑らせる早送りのつまみもある。これは付けない。

- 縦のスクロールと取り合う。WebView の中で右端を掴む操作は、一覧のスクロールの始まりと見分けにくく、つまみに触れたつもりで一覧が動く（逆も）
- 左端には S3 から戻るなぞり（useEdgeSwipe）があり、端の操作を増やすと手ざわりがぶれる
- 指の下の小さなつまみは押しにくく、読み上げでは扱えない。シートなら月を一つずつ名前で選べる

### 5. シート（`web/src/components/past/MonthSheet.vue`）

- DateSheet・PairSheet と同じ下からのシート（`useSheetDrag`）。`body` の直下に出し、開いている間は後ろ（画面と下部ナビ）を `inert`
- 年ごと（新しい年から）に 12 か月のマス（6 列 × 2 段。375pt で 1 マス約 50px、高さ 52px）。記憶のある月だけ押せて、件数を小さく添える。
  無い月は `ink-faint` で薄く置くだけ（`disabled`、`aria-hidden`。読み上げで何十もの「押せない月」を読ませない）。押した札の区切りを朱の淡い地（`aria-current`）で示し、その年が下にあれば頭まで送る
- 年だけの記憶はその年のマスの下に「年だけ」、日付なしはいちばん下に「日付なし」のボタン
- 見出しの下の中身だけをスクロールさせる。紙（`.sheet-paper`）そのものをスクロールさせると、ばねで行きすぎたときのために紙の下へ伸ばした `::after` が中身と一緒に動き、年のマスの上に重なって見えた（headless Chrome で確かめた）

### 6. 触覚と読み上げ

- 触覚（ADR-0011 の 3 節）: 札を押してシートを開くときは鳴らさない（開くだけでは何も変わらない）。月を選んだとき・「いちばん新しいひとことへ」で `select`
- 札は見出し（h2）の中のボタンで、名前は「2025年 11月。年月で探す」（`aria-haspopup="dialog"`）。読み上げは見出しとして区切りを伝え、押すとシートが開くことも伝わる
- シートは `role="dialog"`、`aria-modal`、見出し「年月で探す」にフォーカス。マスは「2025年 11月、3 こ」、年だけは「2023年、年だけ、1 こ」、日付なしは「日付なし、4 こ」
- 選ばずに閉じたら押した札へフォーカスを返す。読み直したら新しい一覧の行き先の札へ置く（シートが閉じきってから。inert の中には置けない）。シートを開いたまま画面を離れたら閉じて inert を外す
- 11/7 の見直し: 読み直しに失敗したら「読み込めませんでした」の一文へフォーカスを置く（`role="alert"` は付けない。フォーカスと両方だと二度読まれる）。
  読み直しを待つ間に画面を離れたら、返ってきても動かさず（KeepAlive で外れている間は、いま見ている別の画面をスクロールしてしまう）、
  戻ったときに useScreen が位置を戻したあと（同じ描き直しの nextTick の後ろ）で行き先へ送り、札へ置く。待つ間に戻ったら取り直さない（取り直しが読み直しの結果を捨て、前の始まりのまま読んでいた）

### 7. 原則との関係

- 記憶はその人のもの: 件数も一覧も `user_id` で絞る（ほかの人の記憶は数えない・混ぜない）。消した記憶は行ごと消えるので件数にも出ない。件数はシートを開くたびに取り直す
- 推測しない: 年だけ・日付なしの記憶を月に割り振らない
- 画面の文言に「AI」「生成」「送信」は無い（check:words）。色は @theme のトークンだけ。動きは既存の `.press`・`.rise-in`・シートの動きだけで、新しい keyframes は足していない

## 時間が無いときに削る順

1. シートを開いたときに、いま見ている年まで送る
2. 年だけ・日付なしのボタン（区切りの札は残る）
3. シート（札は区切りの見出しとして残し、押せなくする）

## 確かめていないこと（実機で見る）

- headless Chrome の 402×874 と 375×812 でしか見ていない。iPhone の WebKit で、sticky の貼り付きと押し出し、セーフエリアの下の位置、札の押しやすさ（見た目 24px、押せる所 44px）、
  シートの中のスクロールと「下へなぞって閉じる」の取り合い（中身がいちばん上のときだけ閉じる）
- VoiceOver で、見出しとしての札の読み上げと、シートのマスの読み順
- デモのデータは月にほぼ 1 件なので、ほとんどの行に札が付く。多すぎると感じたら、年の区切りだけを札にするなどを開発者と決める
