# ADR-0013: 提出前の点検（11/7 夜）で決めたこと

- 日付: 2026-11-07
- 状態: 採用

## 背景

11/7 に届いた案内で、提出締切が 2026-11-08（日）20:00 JST と分かった（それまでは 11/10 14:00 のつもりだった）。
提出物と審査の観点（docs/submission.md）に照らして、6 つの観点（実際の Claude での E2E、本番の手順、履歴と権利、審査員の目、Claude の使い方の棚卸し、デモの道筋のバグ）を読むだけで洗い出し、
指摘ごとに「本当か」「締切までに直す価値があるか」の 2 人の反証役を当てた（100 体、反証に耐えた指摘 14 件）。その直しの中で決めたことを残す。

## 決めたこと

1. **記憶を消すと、その記憶の `ai_runs` も同じ batch で消す**（原則 5「削除は即時」）。これまでは記録を残す作りだった（architecture 4.6）。
   JSON の解析に失敗したときの `error` には、モデルの出力の先頭（本文の引用を含みうる）が入るため、消した記憶の言葉が残っていた。
   裏の処理（候補・想起・写真の候補）が削除の後に `failed` を書こうとしても、行はもう無いので何も戻らない
2. **札の理由の声**: 書いた本人にそっと添える、です・ます調の一文にする。「記憶」「関係」「登場」「可能性」「結びつく」のような説明の言葉と言い切りを使わない。
   言い回しは札ごとに変える。**同じ人物や同じ場所が出てくるだけ**の結びつきや、「〜かもしれない」程度の結びつきでは選ばない（点検で、人物が同じだけの札と分析調の理由が見つかった）。
   変えたあと、元のデモの D1・D4 は札 1 枚、D2 は 2 回とも 0 枚、物語のデータの 6 つの一文も狙いどおりだった（demo/fixtures/README.md）
3. **書く画面で、保存のあと最初の札が届いたら一度だけ札まで送る**。写真や控えの候補があると、札が下部ナビの裏に届いて引用と理由が見えなかった。
   札に下部ナビの高さぶんの `scroll-margin` を持たせる。保存してから指で動かしていたら送らない。動きを減らす設定ではなめらかに動かさない
4. **本番ビルドの向き先の見張り**: `pnpm cap:sync` の先頭で `scripts/check-api-base.mjs` が `VITE_API_BASE` を読み、空や iOS で届かない向き先なら止める
5. **権利のない素材を持ち込まない**: 下部ナビの「きょう」の鉛筆と、候補の控えの鉛筆が既存のアイコン集の形とほぼ同じだったので、自分で描いた絵に替えた（下部ナビは万年筆）
6. **写真の候補（F7、ADR-0012）を締切前に入れた**。デモ 4 本のうち D3 が撮れない状態だったため。実際の Claude で、見本写真 2 枚から 3〜5 秒で「花」「砂丘」「滝」「苔」などが「写真から」で届き、人物の推しはかりは出なかった
7. **デモのデータ**: テストが読む `demo/fixtures/seed.sql`（D1〜D4、16 件）はそのまま残し、撮影用に開発者の筋書きから物語のデータ `demo/fixtures/story.sql`（77 件、人名は架空）を別に作った。
   `seed.sql` は撮影の日の「あの日のひとこと」が「終電で帰った」にならないよう、無関係の 1 件を 1 年まえの 11/8 の記憶に替えた
8. **提出のリポジトリ**: 名前を変えた新しいリポジトリ `neuronest-jp/souieba` に、期間中の履歴だけを出す（ADR-0002 の追記）。
   クラウドのセッションで付いていた `Claude-Session:`・`Co-Authored-By:` のトレーラーと、引き継ぎ資料の端末の情報を除き、作者のメールアドレスは `noreply@neuronest.jp` にする（開発者の判断）。
   手順はプロジェクトの Skill（`.claude/skills/submission-history`）にした
9. **Skills**: この開発では Skills を使っていなかった。くり返した手順（実機への入れ込み、デモの DB の戻し、提出用の履歴づくり）をプロジェクトの Skill にした
10. **ダブルタップの拡大**は viewport で止める（ADR-0011 の 13 節）

## 見送ったこと

- S1 の控えで、短いひとことのとき根拠の引用が本文と同じ文で並ぶ（原則 3 に触れるので変えない）
- Claude の一時的な失敗の再試行（撮るたびに `ai_runs` を見て撮り直す運用にする）
- 本番の deploy・secret・D1 / R2 の作成（開発者が行う。手順は docs/submission.md）
