## 3. この Mac 固有の落とし穴（手順書に無いもの）

1. **`pnpm install` が親の workspace に吸われる。** この worktree は旧構成の checkout（`~/github/souieba`、`pnpm-workspace.yaml` あり）の中にあるため、素の `pnpm install` では `node_modules/.bin` ができない。`pnpm install --ignore-workspace --frozen-lockfile` で入る。`main` にこのブランチが載れば消える問題
2. **`pnpm dev:worker` は LAN に出ない。** `--ip 0.0.0.0` が無い。実機から叩くときは次を直接打つ（docs/setup-capacitor.md 1 節に言及はあるが script が無い）
   ```sh
   pnpm exec wrangler dev --ip 0.0.0.0 --var ENVIRONMENT:development --var INVITE_CODE:dev --var JWT_SECRET:dev-only-secret
   ```
3. **生 IP の `http://` は iOS の ATS に弾かれる。** `NSAllowsLocalNetworking`（2 節）が要る。`NSAllowsArbitraryLoads` にはしない。setup-capacitor.md には書かれていない
4. **署名のチーム ID は `<チーム ID>`。** 証明書名の `(<個人 ID>)` は個人 ID でチーム ID ではない。`project.pbxproj` には書かず、`xcodebuild` の引数で渡した

## 8. 再現コマンド（今日通った手順そのまま）

```sh
# 依存（親 workspace を避ける）
pnpm install --ignore-workspace --frozen-lockfile
export PATH="$PWD/node_modules/.bin:$PATH"

# ローカル D1
wrangler d1 migrations apply souieba --local
wrangler d1 execute souieba --local --file demo/fixtures/seed.sql

# Worker を LAN 公開で起動（別ターミナルで常駐）
wrangler dev --ip 0.0.0.0 --var ENVIRONMENT:development --var INVITE_CODE:dev --var JWT_SECRET:dev-only-secret
curl -s http://<Mac の LAN の IP>:8787/api/health

# 画面 → iOS へ同期（web/.env.local の VITE_API_BASE が埋め込まれる）
vue-tsc -p web/tsconfig.json --noEmit && vite build && cap sync ios

# 実機向け Debug ビルド（初回は SPM 解決で数分）
cd ios/App && xcodebuild -project App.xcodeproj -scheme App -configuration Debug \
  -destination 'id=<UDID>' -derivedDataPath build \
  DEVELOPMENT_TEAM=<チーム ID> -allowProvisioningUpdates build && cd ../..

# インストールと起動（端末のロックを解除しておく）
xcrun devicectl device install app --device <UDID> ios/App/build/Build/Products/Debug-iphoneos/App.app
xcrun devicectl device process launch --device <UDID> jp.neuronest.souieba
```

本番向けに切り替えるときは `web/.env.local` を外し（または `web/.env.production` を置き）、`NSAllowsLocalNetworking` を戻し、同じ手順で入れ直す。
