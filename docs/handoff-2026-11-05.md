## 3. この Mac 固有の落とし穴（手順書に無いもの）

1. **`pnpm install` が親の workspace に吸われる。** この worktree は旧構成の checkout（`~/github/souieba`、`pnpm-workspace.yaml` あり）の中にあるため、素の `pnpm install` では `node_modules/.bin` ができない。`pnpm install --ignore-workspace --frozen-lockfile` で入る。`main` にこのブランチが載れば消える問題
2. **実機から叩くときは `pnpm dev:worker:lan`。** `pnpm dev:worker` を `--ip 0.0.0.0` で LAN に出してはいけない（development は `X-Dev-User` だけで誰にでもなれ、招待コードと署名鍵も公開済み）。
   当初はそうしていたが、自動セキュリティ検査の指摘で 10 節のとおり差し替えた
3. **生 IP の `http://` は iOS の ATS に弾かれる。** `NSAllowsLocalNetworking`（2 節）が要る。`NSAllowsArbitraryLoads` にはしない。setup-capacitor.md には書かれていない
4. **署名のチーム ID は `<チーム ID>`。** 証明書名の `(<個人 ID>)` は個人 ID でチーム ID ではない。`project.pbxproj` には書かず、`xcodebuild` の引数で渡した
5. iOS Simulator の MCP ツールは実機を操作できない。実機は `xcodebuild` + `xcrun devicectl`（8 節）

### 10.1 追記: LAN の Worker を本番と同じ認証に（自動セキュリティ検査の指摘）

最初の `dev:worker:lan` は `wrangler dev --ip 0.0.0.0` に development のまま（`X-Dev-User` 有効、招待コード `dev`、署名鍵 `dev-only-secret`）だった。
同じネットワークの誰でも他人として記憶を読み書きでき、トークンも偽造できたため、scripts/dev-worker-lan.sh に差し替えた:
`ENVIRONMENT=lan`（Worker のコードは変えていない。development 以外なら `X-Dev-User` は無視、署名鍵は 32 文字以上が必須）、乱数の招待コードと署名鍵（`.wrangler/lan-dev.secrets`）、待ち受けは LAN の IP だけ。

確認済み（<Mac の LAN の IP>:8787）: `X-Dev-User` → 401、招待コード `dev` → 401、`dev-only-secret` で偽造したトークン → 401、乱数の招待コード → 200 → `/api/me` 200、`capacitor://localhost` からの preflight 204、`127.0.0.1` と VPN 側の `<VPN の IP>` では待ち受けていない。
動いていた Worker もこの起動に入れ替えた。実機に保存済みのトークンは古い署名鍵のものなので、次に開くとログイン画面に戻る（新しい招待コードで入り直す）。

### 11.1 Android のビルド

JDK 21 を `JAVA_HOME` に向ける（JDK 25 では Gradle 8.14.3 が動かない）。SDK は `~/Library/Android/sdk`（android-34 / 36）。`android/local.properties` は無いので `ANDROID_HOME` を渡す。fish では:

```sh
set -x JAVA_HOME (/usr/libexec/java_home -v 21); set -x ANDROID_HOME $HOME/Library/Android/sdk
pnpm cap:sync; and cd android; and ./gradlew assembleDebug
```
