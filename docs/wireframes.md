# 主要画面ワイヤーフレーム（テキスト）

- 根拠: docs/spec.md 第6節（画面一覧）、第3.1節（主要な流れ）、第5節（非機能）。受け入れ条件は docs/requirements.md の ID で参照する
- デザイン: ADR-0004（カラー・フォント・動き）。トークン名は `web/src/style.css` の `@theme` と同じ
- 画面遷移: docs/architecture.md 第7節（ハッシュ `#today` / `#past` / `#memory/<id>`、vue-router なし）
- 想定幅: スマホ縦 375px。図の枠は内側 40 セル（全角 1 文字 = 2 セル）。PC では中央 560px に収めて同じ構成
- 図中の `[ ]` はボタン、`( )` は入力欄、`▭` は写真、`‹` は戻る

#### 札の構造（RecallCard）

札 1 枚 = `recalls` 1 行。上から順に次の 5 つで、順序は変えない。

| 順 | 要素 | 文言・内容 | トークン・余白 |
|---|---|---|---|
| 1 | 見出し | そういえば。 | `font-display` 22px / 700、`text-ember`。左に 3px の `bg-ember` 縦線（カードの左縁、上下いっぱい）。ember は小さな文字では地とのコントラストが足りないので、必ず 22px 以上の太字で使う |
| 2 | 昔の記憶の日付 | 2025年6月15日（精度 month なら「2025年6月」、year なら「2025年」、unknown なら「いつだったか」） | `text-ink-soft` 14px。見出しとの間 4px |
| 3 | 引用 | 「縁側で梅干しを漬けていた」 | `recalls.evidence` を「」で囲んで逐語で出す。`text-ink` 17px / 1.8。要約も言い換えもしない。長いときは 3 行で切って「…」（全文は開いて読む）。日付との間 8px |
| 4 | なぜ関係があるか | 青梅の季節の記憶です | `recalls.reason`（1〜80 文字）。`text-ink-soft` 14px。引用との間 8px |
| 5 | 開くための領域 | ひらく › | `text-ember` 14px、右寄せ。ただしタップ領域は札全体（最低 44px 高）。押すと `#memory/<related_memory_id>` へ（S3、F5-6） |

- 札は最大 3 枚。縦に 12px あけて並べ、順序は API の順（Worker が保存した先頭から）
- 札の上に「関連する記憶」などの見出しは置かない。「そういえば。」自体が見出し
- 札の中に写真は置かない（S3 で見る）。札は `bg-card` + `border-line`、内側 16px
- 「そうだった」「関係ないかも」は札の上には置かず、S3 で返す（札を小さく、静かに保つ）

### 2.6 想起が失敗したときの状態

Claude 呼び出しの失敗、引用検証で全件破棄、15 秒のポーリング打ち切り（architecture 7.2）のいずれも、画面は 2.5 とまったく同じ。エラー文、再試行ボタン、「しばらくお待ちください」も出さない（第9節「失敗時: 画面には何も出さない」）。

| 状況 | 画面 |
|---|---|
| `ai_runs.status = 'failed'` | 2.5 と同一 |
| `ai_runs.status = 'empty'`（0 件、または検証で全件破棄） | 2.5 と同一 |
| 15 秒で打ち切り、あとから札ができた | S1 には出ない。次に S3 でその記憶を開いたときに「そういえば。」の履歴として見える |

つまり S1 は「保存前」「保存後」の 2 つの状態しか持たず、候補と札は「あれば足される」だけ。ユーザーは待たされていることに気づかない。

## 6. アクセシビリティ

| 項目 | 指針 | 根拠 |
|---|---|---|
| タップ領域 | すべて 44×44px 以上。「そう」「ちがう」「いつ？」「はずす」「消す」「やめる」のような小さな文字のボタンは `padding` ではなく `min-height: 44px` + 透明な余白で確保 | 本書 0 節 |
